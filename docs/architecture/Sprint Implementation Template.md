# Sprint Implementation Template

# Part A – Purpose & Template Overview

## Purpose

The Sprint Implementation Template establishes the standardized format for all AI-assisted implementation requests throughout the development of the Student Online Voting Platform.

Its purpose is to ensure that every implementation sprint provides complete project context, clearly defines the implementation scope, preserves the approved architecture, references applicable business rules, and produces consistent, high-quality engineering outputs.

This template shall be completed before requesting implementation from any AI assistant.

---

## Template Overview

The Sprint Implementation Template serves as the official implementation package for every development sprint.

It provides AI contributors with all necessary project information required to generate implementations that are accurate, secure, maintainable, and fully aligned with the approved Software Requirements Specification (SRS), Software Architecture, Database Architecture, Business Rules, and Engineering Standards.

Every completed template shall represent a single implementation sprint.

---

## Scope

This template shall be used for all AI-assisted implementation activities, including but not limited to:

- Database Engineering
- API Development
- Backend Development
- Frontend Development
- Authentication
- Security Implementation
- Testing
- Documentation
- System Integration
- Future project enhancements

The template shall remain applicable throughout the entire software development lifecycle.

---

## Relationship with the AI Implementation Guide

This template shall be used together with the AI Implementation Guide.

The AI Implementation Guide defines:

- engineering principles.
- AI responsibilities.
- implementation workflow.
- quality standards.
- SQL engineering standards.
- review procedures.

The Sprint Implementation Template applies those standards to individual implementation sprints.

Both documents shall be used together before implementation begins.

---

## Relationship with Project Documentation

The Sprint Implementation Template shall reference the approved project documentation relevant to the assigned sprint.

Depending on the implementation scope, referenced documents may include:

- Software Requirements Specification (SRS)
- Software Architecture
- Database Architecture
- API Specification
- Business Rule Mapping
- Security Documentation
- Testing Documentation
- Architecture Decision Log
- AI Implementation Guide

No implementation shall begin without reviewing the applicable project documentation.

---

## Relationship with Milestones and Sprints

The Student Online Voting Platform is developed using a milestone-based and sprint-based engineering methodology.

Each milestone consists of multiple implementation sprints.

Each sprint focuses on a specific engineering objective and shall produce clearly defined deliverables before the next sprint begins.

The Sprint Implementation Template shall be completed separately for every sprint to ensure that implementation remains incremental, traceable, and consistent with the approved project architecture.

---

## Intended Users

This template shall be used by:

- Software Architect
- Chief Architect
- Database Engineer (Claude)
- Future AI Contributors

Every participant shall perform only the responsibilities assigned within the AI Implementation Guide.

---

## Engineering Principles

The Sprint Implementation Template shall be governed by the following principles:

> **Architecture is approved before implementation.**

> **Documentation shall provide sufficient context before implementation begins.**

> **Every implementation shall be traceable to an approved requirement, business rule, architectural decision, or documented engineering standard.**

> **AI shall assist implementation, not replace architectural decision-making.**

> **Every sprint shall preserve the approved project architecture while producing a complete, reviewable, and testable implementation package.**
